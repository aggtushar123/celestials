# UI Ops Surface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move Pipelines, Communications, Brain and Work (`/pipelines/*`, `/communications`, `/brain/*`, `/work/*`) onto the shared UI primitives in `src/components/ui/`: page titles drawn by the page through `PageHeader` in the Navbar bar, one toolbar, grid-column rows for Pipelines and the Comms queue, flat rows inside the Communications glass shell, `SegmentedControl` for kind and scope, one section-title style on Brain, `PageBody width="reading"` for Work, tiles on `Tile`, states inside cards, the four-size type scale, figures in the body font, and colour only where it means status.

**Architecture:** The same shape as the Records PR. A few primitive gaps are closed first (`ListRow` that is a flex line below its grid breakpoint, a quiet title weight, tab accessible names, link tiles, page controls in the bar's actions slot, inline `Select` that never squeezes). Then each surface switches its markup to the primitives, folder by folder. Brain and Work draw their `PageHeader` once in their route layouts (so the bar survives tab changes and detail views); Pipelines and Communications draw it per page, as Records do. Shared Records parts are changed only where Pipelines needs them (`FilterChips`, `LifecycleCard`, `BoardCard`, `toolbarParts`, `tileParts`), each change keeping the Records output and tests.

**Tech Stack:** React 19 + TypeScript, Vite 8, Tailwind v4 (`@theme` in `src/index.css`, container queries `@container` / `@min-[NNrem]:`), react-router 7, lucide-react, Vitest + Testing Library (jsdom), `scripts/ui-shots.mjs` (Playwright CLI) for screenshots.

**Spec:** `docs/superpowers/specs/2026-10-09-ui-foundations-design.md` (owner-approved 2026-10-09, binding): §2 type scale, §3 numbers, §4 surfaces, §5 controls, §6 page frame, §7 density and colour rules, §9.1 mapping, §9.2 row 2 (Pipelines, Communications, Brain, Work), §9.3 verification, §9.4 house rules and ratchet, §11 owner answers (glass Ask rail approved on Pipelines and Brain, and the Communications shell; account settings untouched). Read it alongside this plan. The Ops audit (`.../scratchpad/ui/ops-findings.md`, systemic issues S1 to S9 and the per-page lists) explains why each change is made; this plan does not depend on it. The Records plan (`docs/superpowers/plans/2026-10-09-ui-records.md`) is the model: where a pattern here says "as Records did", the merged Records code is the reference.

These are the mechanical rules (the Records table, updated for what now exists); each task's table lists the non-mechanical moves.

| Today | Becomes |
|---|---|
| `font-mono-brand tabular-nums`, `font-mono-brand`, or `MONO` (from `portfolio/styles`) on a figure | `NUM` (`tabular-nums`) from `'<relative>/ui'` |
| `font-mono-brand` on words or initials | removed (body font) |
| `font-bold`, `font-extrabold`, `font-medium` | `font-semibold` on headings, labels, buttons; removed on body text |
| `text-[9.5px]`, `[10px]`, `[10.5px]`, `[11.5px]`, `text-xs` | `text-[11px]` (`TYPE.meta`) |
| `text-[12px]` | `13` on controls, inputs, body; `11` on captions, helper text, badges |
| `text-[12.5px]`, `[13.5px]`, `[14px]`, `[14.5px]`, `text-sm`, `text-base` | `text-[13px]` (`TYPE.body`/`TYPE.bodyMuted`); a heading that used 14 becomes `TYPE.title` |
| `text-[16px]`..`[18px]`, `[16.5px]`, `text-lg` | `TYPE.title` |
| `text-[20px]`, `[23px]`, `[24px]`, `text-xl`, `text-2xl` | `TYPE.display` |
| A section heading `text-[11px] font-semibold uppercase tracking-wider text-ink-muted` (Brain's `SECTION_TITLE`, Work's, the detail views' `font-bold uppercase`) | `TYPE.title` on the `h2`/`h3`; a sub-heading inside a card is `TYPE.label`. | `text-danger` / `text-warning` / `text-success` / `text-info` on **text** | `text-danger-ink` / `text-warning-ink` / `text-success-ink` / `text-info-ink` (dots, bars, icons, SVG fills keep the plain tokens) |

### Task 1: Before screenshots and the primitive gaps the Ops surface needs

**Files:**
- Modify: `src/components/ui/List.tsx`, `Tabs.tsx`, `Tile.tsx`, `PageHeader.tsx`, `Select.tsx`, `src/pages/dev/UiGallery.tsx`
- Test: `src/components/ui/{List,Tabs,Tile,PageHeader,Select}.test.tsx`

**Interfaces:**
- Consumes: the primitives as Records left them.
- Produces (later tasks rely on these exact names):
  - `ListRow` gains `gridAt?: { row: string; cell: string }` (literal classes such as `{ row: '@min-[60rem]:grid', cell: '@min-[60rem]:block' }`): below that breakpoint the row is one flex line (leading, title and meta, trailing, actions) and every `cells` wrapper is `hidden`; from it the row is a grid on `columns`. Without `gridAt` a `columns` row stays a grid at every width (Records' rows).
  - `ListRow` gains `strong?: boolean` (default `true`): `false` sets the title in `font-normal` (a read message beside unread ones).
  - `TabItem` gains `ariaLabel?: string`, the tab's accessible name when its words and count need saying differently ("Waiting on you, 3 waiting").
  - `Tile` gains `to?: To`, `replace?: boolean`, `current?: boolean`: with `to` the tile is a `Link` (same anatomy as the `onOpen` button tile), `aria-current="location"` and the subtle fill while `current`; `onOpen` runs on its click; `buttonLabel` names it.
  - `PageHeaderActions({ children })` from `ui/PageHeader.tsx` (re-exported by `ui/index.ts` through `export * from './PageHeader'`): from `sm` it portals `children` into the Navbar's actions slot inside `<div data-page-actions="bar" className="order-first mr-3 flex items-center gap-2">` (before the Ask controls); below `sm`, or with no slot, it renders them in place inside `<div data-page-actions="inline" className="flex">`.
  - `Select` with `labelPosition="inline"`: its wrapper is `flex shrink-0 items-center gap-2`, so a toolbar row wraps instead of squeezing the select.

 *  count lives in the toolbar. Organizations, Accounts and Pipelines. */
export function ActiveFilterChips<P>({
  chips,
  onChange,
  onClearAll,
}: {
  chips: ActiveFilter<P>[];

  onClearAll: () => void;

        Clear all
      </button>

}

import type { ScopeKey, ScopeOption } from '../../features/brain/brainTypes';
import { SegmentedControl, TYPE } from '../ui';

/** Me · My team · Company (spec §2.2): only the scopes the server offered,
 *  one segmented control at every width (UI foundations spec §5.3: three
 *  short options fit a phone). One scope is a label, not a control. */
export function ScopeSwitch({ scopes, value, onChange }: { scopes: ScopeOption[]; value: ScopeKey; onChange: (key: ScopeKey) => void }) {
  if (scopes.length === 1) return <p className={TYPE.bodyMuted}>{scopes[0].label}</p>;
  return (
    <SegmentedControl<ScopeKey>
      label="View"
      value={value}
      options={scopes.map((scope) => ({ value: scope.key, label: scope.label }))}
      onChange={(key) => {
        if (key !== value) onChange(key);
      }}
    />
  );
}

function tracks(columns: string): number[] {
  const template = /grid-cols-\[([^\]]+)\]/.exec(columns)![1];
  return template.split('_').map((track) => {
    const min = /^minmax\(([\d.]+)rem,/.exec(track);
    if (min) return Number(min[1]);
    const fixed = /^([\d.]+)rem$/.exec(track);
    if (fixed) return Number(fixed[1]);
    throw new Error(`unknown track ${track}`);
  });
}

describe('the Communications row grids', () => {
  it.each([
    ['queue', QUEUE_COLUMNS, QUEUE_TRACKS_REM],
    ['mail', MAIL_COLUMNS, MAIL_TRACKS_REM],
  ] as const)('the %s grid fits its breakpoint: tracks, gaps and the row padding', (_name, columns, expected) => {
    expect(tracks(columns)).toEqual([...expected]);
    const minimum = tracks(columns).reduce((a, b) => a + b, 0) + (tracks(columns).length - 1) * QUEUE_GAP_REM + 2;
